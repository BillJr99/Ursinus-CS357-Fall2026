## Model 1: Why Synthetic Data?

High-quality labeled data is the fuel of modern machine learning, but it is expensive, slow, or sometimes impossible to obtain:

- **Medical data** requires expert annotation (radiologists, pathologists), de-identification, and IRB approval. A single labeled CT scan may cost hundreds of dollars.
- **Legal data** is confidential and jurisdiction-specific. Training a legal reasoning model requires case law that cannot be shared freely.
- **Specialized domains** (semiconductor design, drug interaction prediction, rare language translation) have few practitioners and even fewer labeled examples.
- **Future scenarios** don't exist yet: you cannot collect data about how an agent should handle a new type of cyberattack before that attack type exists.

**Synthetic data** is data that is artificially generated rather than collected from the real world. It can be generated by rules, by simulation, or by a generative AI model. The goal is to fill the data gaps listed above.

### Four Use Cases for Synthetic Data

| Use Case | What Synthetic Data Generates | Real-World Benefit | Key Risk | Example |
|----------|------------------------------|-------------------|----------|---------|
| **Instruction tuning** | Diverse (prompt, response) pairs | Scale fine-tuning without expensive human labeling | Model learns the generator model's biases; mode collapse | Alpaca dataset (Stanford, 2023) |
| **Adversarial robustness** | Edge-case prompts the model normally wouldn't see | Better robustness to unusual inputs and attacks | Synthetic adversarials may not cover real-world adversarial strategies | Red-teaming augmentation |
| **Privacy preservation** | Statistically similar fake records replacing real ones | Share datasets safely without exposing individuals | Residual privacy leakage if the synthetic distribution reveals real records | Synthetic patient records |
| **Simulation environments** | Agent training scenarios (e.g., code review sessions, customer service calls) | Scale agent training without real user interactions | Sim-to-real gap: agent learns behaviors that work in simulation but fail in deployment | OpenAI Codex training environments |

## Model 2: Generating Synthetic Instruction Data

The most widely used form of synthetic data for LLM training is **instruction-following data**: pairs of (instruction, response) that teach a model how to respond helpfully to natural language requests.

### Self-Instruct (Wang et al., 2022)

Self-Instruct is the pipeline behind several influential open-source instruction-tuned models:

1. Start with a **seed set** of ~175 human-written instruction examples.
2. Prompt a large model (originally GPT-3) to generate new instructions by analogy with the seed set.
3. For each new instruction, prompt the model to generate a corresponding response.
4. Apply **quality filters**: remove duplicates, near-duplicates, toxic content, and low-quality responses.
5. Add passing instances to the dataset.
6. Repeat from step 2, using the growing dataset as the seed.

Stanford's **Alpaca** model (2023) applied this pipeline using GPT-3.5 to generate 52,000 instruction pairs at a cost of roughly $500 — far cheaper than human labeling at scale.

### Evol-Instruct (WizardLM)

Evol-Instruct takes a different approach: instead of generating new instructions from scratch, it **evolves** existing simple instructions into harder ones through iterative rewriting. Evolutions include:

- **Add constraints:** "Write a function that sorts a list" → "Write a function that sorts a list without using any built-in sorting functions, in O(n log n) time."
- **Deepen complexity:** "Explain photosynthesis" → "Explain photosynthesis to a biologist who is skeptical that recent research on quantum coherence in light-harvesting complexes changes the classical explanation."
- **Require multi-step reasoning:** Single-step questions become chains of reasoning with intermediate conclusions.

### Quality Filtering Pipeline

```
seed_instructions
    → generate_variants(LLM)
    → filter_quality(judge_LLM_or_rules)
    → deduplicate(exact + semantic similarity)
    → measure_diversity(embedding_spread)
    → add_to_dataset
    → loop
```

**Quality filter criteria:**

- Length: response is not trivially short or padded
- Coherence: response addresses the instruction
- Non-duplication: cosine similarity to existing items below threshold
- Safety: no toxic or harmful content

## Model 3: Synthetic Data for Agent Training

Instruction-following pairs are not the only form of synthetic data used in AI training. Agents require **trajectories** — sequences of observations, decisions, actions, and outcomes.

### Synthetic Trajectories

An agent trajectory is a tuple sequence: `(observation_1, action_1, result_1, observation_2, action_2, result_2, ...)`.

Generating synthetic trajectories allows agent training to scale beyond available human demonstrations:

- **Verified code problems:** Generate a programming problem, generate a candidate solution, run the solution in a sandbox, use pass/fail as a ground-truth label. OpenAI's Codex training data included synthetic problems with verified solutions generated this way.
- **Customer service dialogs:** Generate a synthetic customer persona, a synthetic complaint, and a range of synthetic agent responses rated by a judge model. Provides training signal without accessing real user data.
- **Tool-use chains:** Generate tasks that require specific tool sequences, execute them in a sandboxed environment, label trajectories by task completion.

### Synthetic Evaluation Sets: The "LLM Generates Its Own Exam" Pattern

You can use a model to generate its own evaluation questions — for example, to quickly build a benchmark for a new domain. The pipeline:

1. Prompt the model: "Generate 20 challenging questions about [domain] that require [capability]. For each, provide the correct answer."
2. Filter generated pairs for quality and correctness.
3. Use the resulting pairs as a benchmark to evaluate the same or a different model.

**Critical pitfall:** A model will perform better on questions it generated than on questions it did not. The generated exam is easier for the model that wrote it, and this inflates apparent capability. This is sometimes called the **self-evaluation inflation** problem.

## Further Reading

- Wang, Y. et al. "Self-Instruct: Aligning Language Models with Self-Generated Instructions." ACL 2023. The foundational paper for synthetic instruction generation pipelines.

- Shumailov, I. et al. "The Curse of Recursion: Training on Generated Data Makes Models Forget." arXiv:2305.17493 (2023). Introduces and formalizes the model collapse phenomenon.

- Taori, R. et al. "Alpaca: A Strong, Replicable Instruction-Following Model." Stanford CRFM Blog (2023). Describes the Alpaca pipeline and its known limitations; a good starting point for critiquing self-instruct quality.

- Xu, C. et al. "WizardLM: Empowering Large Language Models to Follow Complex Instructions." arXiv:2304.12244 (2023). The Evol-Instruct paper; describes the instruction evolution methodology in detail.
